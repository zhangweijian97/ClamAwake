# 实施单：保活与系统级防睡合并为单开关（v0.3.5）

日期：2026-11-21。目标卡：goal-141d32。状态：已实施已验收（实弹两轮通过，2026-11-21）。

## 需求（用户原话）

「两个功能合并到一个开关中。开就一起开，关也一起关。因为，如果只防止睡眠，不开启镜像屏幕，那么就会出现合盖但是屏幕还亮着的情况，这是不可接受的。」

## 问题本质

原设计有两个独立开关：

- **保活**：虚拟屏（`--mirror-main` 镜像主屏）+ `caffeinate -d`。合盖进 clamshell 模式，内屏熄灭。
- **系统级防睡**：`pmset -a disablesleep 1`（菜单独立项 + CLI `sleepguard on|off`）。

非法组合：**防睡开 + 保活关**——合盖后系统不睡，但没有显示器承接显示，内屏背光保持亮。合并成一个开关 = 堵死走进非法组合的路径。

## 合并语义

- **开保活**：`engine.start()`（建屏+caffeinate，即时）+ `sleepGuard.setEnabled(true)`（pmset 禁睡，弹管理员授权；pmset 已是 1 则跳过不弹）。
- **关保活**：`engine.stop()`（拆屏）+ 防睡自动回收（由 phase 变化观察统一触发 `setEnabled(false)`；覆盖用户主动关、引擎意外死亡、启动失败三路）。
- **单独开防睡的入口全部删除**（菜单独立项、CLI `sleepguard on|off`）；矛盾态（防睡仍开+保活已停）菜单显示警告行 +「恢复系统睡眠默认」项（唯一保留的单独关防睡出口，仅矛盾态出现）。

## 文件级改动

### 1. `shell/Sources/ClamAwake/SleepGuard.swift`

`setEnabled` 重写：目标值已是当前值 → no-op（免弹窗）；`isApplying` 中收到新请求 → 记 `pendingTarget`，完成后执行。完整新方法体：

```swift
    /// 开/关系统级防睡（会弹管理员授权窗；用户取消 → 报错、状态不变）。
    /// 已是目标值 → no-op（pmset 是持久设置，值没变就不弹窗）；
    /// isApplying 中收到新请求 → 记入 pendingTarget，当前写入完成后紧接着执行
    /// （堵「开保活的 osascript 飞行中引擎失败，回收调用被 isApplying 吞掉」的窗口）。
    private var pendingTarget: Bool?

    func setEnabled(_ on: Bool) {
        if isApplying {
            pendingTarget = on
            return
        }
        refresh()
        if isEnabled == on { return }
        isApplying = true
        lastError = nil
        let cmd = on ? "pmset -a disablesleep 1" : "pmset -a disablesleep 0"
        let action = on ? "禁用" : "恢复"
        let script = "do shell script \"\(cmd)\" with administrator privileges"
            + " with prompt \"ClamAwake 需要管理员权限来\(action)系统睡眠设置（pmset）\""
        DispatchQueue.global().async { [weak self] in
            let result = runOSascript(script)
            DispatchQueue.main.async {
                guard let self else { return }
                self.isApplying = false
                if let message = result.1 { self.lastError = message }
                self.refresh()
                if let pending = self.pendingTarget {
                    self.pendingTarget = nil
                    if self.isEnabled != pending {
                        self.setEnabled(pending)
                    }
                }
            }
        }
    }
```

（`pendingTarget` 存储属性与 `isEnabled` 读数对齐：pending 与写入结果相同就不重复执行。）

### 2. `shell/Sources/ClamAwake/ClamAwakeApp.swift`

a) **开保活联动**——`setKeepAlive(_:)` 的 `if on` 分支加一行：

```swift
    private func setKeepAlive(_ on: Bool) {
        if on {
            engine.start()
            sleepGuard.setEnabled(true)   // 合并开关：开保活同时禁系统睡眠（已是 1 则免弹窗）
            UserDefaults.standard.set(true, forKey: "resumeKeepAliveOnLaunch")
        } else {
            engine.stop()   // 防睡回收由 observeEnginePhase 的 phase 观察统一触发
            UserDefaults.standard.set(false, forKey: "resumeKeepAliveOnLaunch")
        }
        refreshIcon()
    }
```

b) **防睡回收观察**——`install()` 里加第二个 sink（与现有 `engine.$phase` 图标 sink 并列），带前一状态跟踪，只在 starting/running → stopped/failed 的变化沿触发：

```swift
        // 合并开关的关侧：保活一旦停了（用户主动关 / 引擎意外死亡 / 启动失败），
        // 系统级防睡必须跟着撤——防睡单独残留 = 合盖不睡且内屏背光保持亮（不可接受状态）。
        // 只看变化沿（starting/running → stopped/failed），app 启动时的初始 .stopped 不触发
        // （存量矛盾态只走菜单警告行，避免开机自动弹管理员授权窗）。
        var lastPhase: EngineController.Phase = .stopped
        engine.$phase
            .receive(on: RunLoop.main)
            .sink { [weak self] phase in
                let wasActive: Bool
                switch lastPhase {
                case .starting, .running: wasActive = true
                default: wasActive = false
                }
                let nowInactive: Bool
                switch phase {
                case .stopped, .failed: nowInactive = true
                default: nowInactive = false
                }
                lastPhase = phase
                if wasActive && nowInactive {
                    self?.sleepGuard.refresh()
                    if self?.sleepGuard.isEnabled == true {
                        self?.sleepGuard.setEnabled(false)
                    }
                }
            }
            .store(in: &cancellables)
```

注意：`wasActive && nowInactive` 中 starting→failed（启动失败）也命中——此时保活没成，防睡必须回收，正确。用户主动 stop 路径：`engine.stop()` 同步置 `.stopped` → sink 触发回收（`setKeepAlive(false)` 里不显式调，单点触发）。

c) **菜单**——`buildMenu()` 删除整个「系统级防睡」块（`let sleep = NSMenuItem(...)` 到 `if sleepGuard.isApplying { menu.addItem(caption("等待管理员确认…")) }` 四行），在原位置改为矛盾态警告 + 恢复项：
