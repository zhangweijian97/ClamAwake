# 实施单：插电档与电池档重构（v0.3.7）

日期：2026-11-21。目标卡：goal-416a6d。UI 快照已经用户过目认可。

## 语义定义（核心）

档位从「保活开关的内容」（0.3.6）改为**机器的常驻配置**，独立于保活开关：

- **插电档（plugged）**：保活开关 = 虚拟屏 + caffeinate 断言，随开关生灭，零密码。
- **电池档（battery）**：选档时拉 pmset 闸一次（弹一次管理员授权），**闸常驻**——不随保活开关撤、退出 app 不撤；保活开关本身与插电档相同。
- 切回插电档 = 撤闸（弹一次授权，若闸在）。
- 电池档 + 保活关 = 合法状态（用户选了常驻禁睡），不再当矛盾态。
- 命名中英：插电档 / 电池档；Plugged-in mode / Battery mode。

## 实测背景（写进 README 的依据）

2026-11-21 20:37 本机电池供电（71%）合盖，系统日志 `Entering Sleep state due to 'Clamshell Sleep'`——虚拟屏在场、`-d -s` 断言在场仍睡：clamshell 模式要求接电源，电池合盖走硬件事件路径，断言与虚拟屏均无效，唯 pmset disablesleep 全覆盖。

## 文件级改动

### 1. `shell/Sources/ClamAwake/EngineController.swift` — caffeinate 泄漏修复

`engineDidTerminate` 的非 stopRequested 分支（意外退出路径）补 caffeinate 连带清理。现有代码：

```swift
        switch phase {
        case .starting:
            ...
        default:
            // 意外退出：屏随引擎进程一起消失，状态回落到已停止
            phase = .stopped
        }
```

改为（两个分支都要清——引擎死了 caffeinate 的断言就没了服务对象，留着只会挡屏幕自动息屏并随意外次数累积）：

```swift
        switch phase {
        case .starting:
            // 启动失败：caffeinate 同步清理，不留半启动残件
            if let p = caffeinateProcess { gracefulTerminate(p) }
            caffeinateProcess = nil
            ...
        default:
            // 意外退出：屏随引擎进程一起消失，状态回落到已停止；caffeinate 连带清理（否则孤儿断言常驻）
            if let p = caffeinateProcess { gracefulTerminate(p) }
            caffeinateProcess = nil
            phase = .stopped
        }
```

```swift
    /// 切换档位（菜单/CLI 同路径）。闸的生灭只发生在换档：
    /// 切电池档 → 拉闸（弹一次授权；闸已在则免弹）；切插电档 → 撤闸（弹一次授权；闸已撤则免弹）。
    private func setKeepAliveMode(_ mode: KeepAliveMode) {
        keepAliveMode = mode
        sleepGuard.refresh()
        if mode == .battery {
            if !sleepGuard.isEnabled {
                sleepGuard.setEnabled(true)
            }
        } else if sleepGuard.isEnabled {
            sleepGuard.setEnabled(false)
        }
    }
```

e) **电源状态检测与护栏**——StatusBarController 内新增：

```swift
    // MARK: - 电源状态（IOPS）：保活中 + 电池供电 + 插电档 = 插电档挡不住合盖，给护栏
    private var powerSource: CFRunLoopSource?

    /// 当前是否在用电池（无电池设备/读不到按接电处理）
    static var onBattery: Bool {
        guard let snapshot = IOPSCopyPowerSourcesInfo()?.takeRetainedValue(),
              let sources = IOPSCopyPowerSourcesList(snapshot)?.takeRetainedValue() as? [CFTypeRef] else {
            return false
        }
        for ps in sources {
            guard let desc = IOPSGetPowerSourceDescription(snapshot, ps)?.takeUnretainedValue() as? [String: Any],
                  let state = desc[kIOPSPowerSourceStateKey] as? String else { continue }
            if state == kIOPSBatteryPowerValue { return true }
        }
        return false
    }

    /// 电源状态护栏：保活开着 + 电池 + 插电档 → 图标警示 + 菜单一键换档
    private var guardTripped: Bool {
        engine.isProtecting && Self.onBattery && keepAliveMode == .plugged
    }
```

## 收尾批（2026-11-21 深夜，定位定稿后）

定位定调：首要用户=携带电脑移动的人 → **默认档改电池档**；插电档=第二类用户（电脑不挪窝）的正解，非进阶选项。

1. **默认值翻转**：`keepAliveMode` getter 迁移逻辑改——`"plugged"|"normal"` → 插电档，**其余（含缺省、battery、power）→ 电池档**。
2. **开保活补闸（电池档完整性）**：`setKeepAlive(true)` 分支加——电池档且闸未拉时补拉（新用户首次开保活弹一次授权，此后闸常驻、开关零密码）。resume 路径不补（pmset 持久，正常场景闸在；异常场景菜单状态行可见，下次手动开关自愈——取舍记录）。
3. **菜单文案场景化**：电池行「电池——带着电脑走，合盖必不睡（授权一次）」；插电行「插电——电脑不挪窝，零密码不动系统设置」。
4. **README 承诺分级**：「合盖必不睡」承诺只挂机制级（电池档）；插电档标注本机多日实测；其他机型留反馈口（「不同机型行为可能不同，遇到问题请开 issue」）。
