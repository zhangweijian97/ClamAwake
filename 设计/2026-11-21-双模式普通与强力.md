# 实施单：双模式——普通模式（零密码）与强力模式（pmset 拉闸）（v0.3.6）

日期：2026-11-21。目标卡：goal-913ef4。

## 需求与决策（用户定调）

0.3.5 把 pmset 并进单一开关后，每次开关都要输管理员密码——产品摩擦不可接受（用户：「要从产品的角度考虑」）。定调：分两个模式。

- **普通模式（默认）**：虚拟屏镜像 + caffeinate 断言（`-d -s`）。零密码、随开关生灭、结构上无残留。
- **强力模式**：普通 + pmset `disablesleep 1` 全覆盖拉闸（电池合盖等边缘场景兜底）。开保活弹一次密码、关保活弹一次密码（pmset 已是目标值则免弹）。

命名沿用用户原话：普通模式 / 强力模式（英文 normal / power）。

## 机制要点

- 模式=持久设置（UserDefaults `keepAliveMode`，默认 normal），保活开关仍是单开关——模式是开关内容的档位。
- 切换模式时把 pmset 对齐新模式：切到强力且保活开着 → 补拉闸（弹授权）；切到普通 → 撤闸不留残留（弹授权，若开着）。
- 0.3.5 的防睡回收 sink（phase 变化沿 starting|running→stopped|failed 时若 `sleepGuard.isEnabled` 则回收）**保留不动**：普通模式下 isEnabled 恒 false 天然 no-op；强力模式行为同 0.3.5。
- caffeinate 从 `-d` 加固为 `-d -s`（防显示睡眠+防系统睡眠两张断言票，零成本）。
- 矛盾态警告行与「恢复系统睡眠默认」出口保留（强力模式 SIGKILL 残留的兜底）。

        if on {
            engine.start()
            if keepAliveMode == .power {
                sleepGuard.setEnabled(true)   // 强力模式：同时拉 pmset 闸（已是 1 则免弹窗）

            UserDefaults.standard.set(false, forKey: "resumeKeepAliveOnLaunch")

    }

d) 模式设置公共方法 + 菜单动作（放在 toggleLaunchItem 附近）：

```swift
    /// 设置保活模式（菜单/CLI 同路径）。切换时把 pmset 对齐新模式：
    /// 切到强力且保活开着 → 补拉闸（弹授权）；切到普通 → 撤闸不留残留（弹授权，若开着）。
    private func setKeepAliveMode(_ mode: KeepAliveMode) {
        keepAliveMode = mode
        sleepGuard.refresh()
        if mode == .power {
            if keepAliveOn && !sleepGuard.isEnabled {
                sleepGuard.setEnabled(true)
            }
        } else if sleepGuard.isEnabled {
            sleepGuard.setEnabled(false)
        }
    }

    @objc private func toggleKeepAliveMode() {
        setKeepAliveMode(keepAliveMode == .normal ? .power : .normal)
    }
```
