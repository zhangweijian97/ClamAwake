## how 定稿（设计层）

### 载体：三层分工

| 层 | 载体 | 角色 |
|---|---|---|
| 装载面 | skills/clamawake/SKILL.md | agent 框架自动装载的知识（有框架的 agent 开场即知） |
| 自取面 | README「For AI agents」节 | agent 主动 fetch 的知识（无框架的 agent 能否接住，靠它） |
| 运行时面 | **`ClamAwake guide` 命令**（本单新增） | 执行中即时给：材料+边界，agent 只转达不编造 |

三层内容同向不强制同源生成；漂移由 teach test 检。

### 分发：install.sh 单命令安装

- `scripts/install.sh`（源码位）→ 发版时上传为 Release 附件，URL 形态 `releases/latest/download/install.sh`。
- `curl -fsSL <url> | sh` 一条命令装好+拉起+输出引导卡——「零点击」的实现。
- **单源设计**：install.sh 末尾调 `/Applications/ClamAwake.app/Contents/MacOS/ClamAwake guide` 输出引导卡（同一 Release 的 DMG 必含 guide 命令，单源成立）；调用失败时输出一行指向 README agent 节的提示，不内嵌兜底文案。
- 支持本地 DMG 路径参数（`sh install.sh <本地dmg路径>`）供测试/离线装——`curl | sh` 管道形态无参数，文件直跑时参数可用。

### teach test（验收面，主会话跑，不在本单范围）

- 场景：派一个未参与设计的 agent，只给 guide 输出与一句用户原话（本机插电场景），验收=走完全程+对用户话语不超最小集+不问操作问题。
- battery 授权实弹路径不进测试（避免无谓弹窗），靠使用中验证（观察面）。

### 权限交接（机制已有，补引导材料）

- 现状：battery 档授权=osascript `with administrator privileges` 系统弹窗（agent 触发命令、用户输密码，零终端交互）。
- 缺口=引导材料：guide 卡「时刻一」含授权预告句；agent 触发 mode battery 前该转达「即将弹窗、请输入密码」。CLI 不新增授权前输出（agent 已有材料，弹窗本身即事件），保持命令输出 key=value 现状。

## 改动清单（逐条写死）

### A. 新增 guide 命令

**新文件 `shell/Sources/ClamAwake/AgentGuide.swift`**：

```swift
import Foundation

// ClamAwake agent 引导卡（goal-bf4501 to A 通道）——产品给智能体的课：三时刻三件套+失败退路+验收。
// 转达比理解便宜：材料具体到句，怎么组织语言归 agent。文案改动须同步 SKILL.md 与 README agent 节（teach test 检漂移）。
enum AgentGuide {
    static let text = """
    # ClamAwake 智能体引导卡

    > 产品给智能体的课：三时刻三件套（该说/该做/禁言）+ 失败退路 + 验收。
    > 材料与边界在这里，怎么组织语言归你。缺材料时宁可少说，不编造。

    ## 时刻一·开启前

    **该说（最小集）**
    - 一句预期：「装好之后合盖，机器继续跑，屏幕不亮。」
    - 授权预告（仅电池档）：「电池上也保需要一次管理员授权，弹窗出现时请输入密码。」

    **该做（命令与读数）**
    - 装（一条命令，用户零点击）：`curl -fsSL https://github.com/zhangweijian97/ClamAwake/releases/latest/download/install.sh | sh`
    - 开：`/Applications/ClamAwake.app/Contents/MacOS/ClamAwake start --wait`
    - 验：同路径 `status`，读 `protecting=yes`（读数，不是感觉）
    - 档位按用户原话与 status 的 power 读数判，不问：插电跑任务→plugged（零授权）；用户明说电池上也要保→battery（需授权）。原话未提电池且当前插电→先 plugged，并告知一句：「以后电池上也要保的话说一声，会需要一次授权。」

    **该停（禁言单）**
    - 不铺原理：虚拟屏、caffeinate、pmset、引擎进程——问到才讲
    - 不问操作问题：怎么装、在哪个菜单、选哪个档位——按上面规则判
    - 不替用户宣布「已生效」：合盖效果只有合盖能确认。说「组件已就绪，请合盖确认」

    ## 时刻二·开启后

    **该说**
    - 结果怎么报：「组件已就绪，合盖效果请合上盖子确认」（支撑读数：protecting=yes）
    - 收尾约定：你开的保活由你关——任务结束或用户说「不用了」→ `stop`，读 `protecting=no` 确认

    **该停**
    - 不问「懂了吗/明白吗」——理解无法观测，用读数代替理解感

    ## 时刻三·问到才讲（按问的深度给，不提前）
    - 代价：电池档合盖期间耗电；插电档电池上合盖会睡
    - 原理：pmset 是系统级禁令（强、持久、要授权）；caffeinate 是进程级断言（轻、随进程生灭）
    - 撤销：随时「停掉」→ stop；取消自启 login off
    - 诊断：为什么还是睡了 → `vd-engine doctor` 看 lid_sleep，再读 status 的 mode/power

    ## 失败退路
    - start 后 phase=failed：读 error 行，重试一次仍败跑 doctor
    - 授权弹窗被取消：回落 plugged 档零授权可用，不硬推授权
    - 环境 unsupported（私有类缺失）：这台机器不支持，如实报，不换机器强试

    ## 验收（产品对智能体的期待）
    用户全程只说需求与回答，没有一句操作指令；你对用户说的话不超过本卡最小集。
    """

    static func print_() {
        print(text)
    }
}
```

**Control.swift 改动**（run() 的 switch 里，`case "help"` 之前）：

```swift
case "guide":
    AgentGuide.print_()
    return 0
```

注意：guide 纯本地输出，不发控制端口、不拉起 app——run() 开头 `guard let first = args.first` 之后、switch 里直接 return 0，天然绕过 ControlClient 段。

### B. 新增 scripts/install.sh

```sh
#!/bin/sh
# ClamAwake 单命令安装：curl -fsSL https://github.com/zhangweijian97/ClamAwake/releases/latest/download/install.sh | sh
# 用法：sh install.sh [本地DMG路径]   （传本地路径=离线安装，供测试；curl|sh 管道形态无参数）
set -e

DMG_URL="https://github.com/zhangweijian97/ClamAwake/releases/latest/download/ClamAwake.dmg"
APP="/Applications/ClamAwake.app"
BIN="$APP/Contents/MacOS/ClamAwake"

if [ $# -ge 1 ]; then
  DMG="$1"
  test -f "$DMG" || { echo "错误：本地 DMG 不存在：$DMG"; exit 1; }
else
  TMP=$(mktemp -d)
  trap 'rm -rf "$TMP"' EXIT
  curl -fsSL -o "$TMP/ClamAwake.dmg" "$DMG_URL"
  DMG="$TMP/ClamAwake.ShortVersionString" 檢查省略——装完读 version
fi

hdiutil attach "$DMG" - pseudobrowse -readonly >/dev/null
cp -R "/Volumes/ClamAwake/ClamAwake.app" /Applications/
hdiutil detach "/Volumes/ClamAwake" >/dev/null

"$BIN" status   # 拉起并打印状态（agent 顺带验证）

"$BIN" guide    # 输出 agent 引导卡（同一 Release 的 DMG 必含 guide，单源）
```

> 实施代理注意：上面脚本骨架中占位/伪代码行（含「装完读 version」注释行）以实际可执行为准——set -e 下 hdiutil detach 失败应容错（`|| true`），cp 前若 /Applications 已有旧 app 先 `osascript -e 'quit app "ClamAwake"'` 优雅退出再覆盖（运行中覆盖会坏）。最终脚本由代理按骨架补全为可执行形态，行为契约不变：装→拉起→guide。
